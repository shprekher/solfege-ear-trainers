# Диктанты: использование, бот и развёртывание

## Как устроено

Сайт остаётся статическим. Существующие семь тренажёров, их звук и база прогресса не меняются. Новый раздел: `dictations.html` → отдельная страница занятия `dictation.html?id=…` с датой получения и необязательным описанием.

Отдельный **личный Telegram-бот** работает на постоянно включённом компьютере или небольшом VPS. Он принимает пересланные тексты, музыку и голосовые сообщения, скачивает оригинальные файлы и выдаёт переносимый набор `.solfege`. Пользователь скачивает набор из Telegram и выбирает его на сайте через «Импортировать набор». Автоматического облачного обмена между сайтом и ботом нет: один явный импорт нужен, чтобы не вводить сервер, аккаунты и хранение частных записей на публичном хостинге.

Это рабочая интеграция через файлы, а не Telegram Mini App. Токен бота никогда не поступает в браузер. Приложение не загружает пользовательские записи и отметки на сайт.

## 1. Создать своего бота

1. В Telegram откройте **официального @BotFather**.
2. Отправьте `/newbot`, задайте отображаемое имя и свободное имя пользователя, заканчивающееся на `bot`.
3. Сохраните выданный токен в личном файле окружения на компьютере бота. **Не присылайте токен в чат, не вставляйте в HTML/JavaScript, GitHub, скриншоты и журналы.** Если токен раскрыт, перевыпустите через BotFather.
4. Бот обслуживает только личные чаты и пользователей из списка разрешённых ID. Группы и каналы игнорируются. При пустом списке доступна только команда `/id`, скачивание записей запрещено.

Бот создаётся владельцем в Telegram: одного размещения Python-кода на Tuqo недостаточно. Для запуска нужны действующий токен и доступ компьютера к `api.telegram.org` по HTTPS.

## 2. Первый запуск на компьютере

Нужен **Python 3.9+** с системной базой часовых поясов (на Linux пакет `tzdata`). Библиотеки Python, Node.js, FFmpeg и входящие сетевые порты для работы бота не нужны. FFmpeg используется только в необязательных тестах для генерации синтетического OGG/Opus.

В приватном терминале задайте переменные (значение токена вводите только локально):

```sh
export TELEGRAM_BOT_TOKEN='ваш-токен-из-BotFather'
export DICTATION_DATA_DIR="$HOME/.local/share/solfege-dictation-bot"
python3 bot/dictation_bot.py
```

Откройте созданного бота, нажмите Start и отправьте `/id`. Он ответит числовым ID. Остановите процесс Ctrl+C, добавьте свой ID и запустите снова:

```sh
export TELEGRAM_ALLOWED_USER_IDS='123456789'
export DICTATION_TIMEZONE='Europe/Moscow'
export DICTATION_SITE_URL='https://solfege-ear-trainers.tuqo.ru/dictations.html'
python3 bot/dictation_bot.py
```

Адрес в `DICTATION_SITE_URL` замените на свой фактический сайт. Несколько разрешённых пользователей: ID через запятую. Данные разделены по пользователю; команды не могут экспортировать или удалить чужие занятия. Токен не меняйте между запусками без необходимости. После первого запуска переменные удобнее хранить в файле окружения с правами `600`; пример — `bot/.env.example`. Не размещайте этот файл или каталог данных внутри обслуживаемого веб-сервером каталога.

По умолчанию данные находятся в `~/.local/share/solfege-dictation-bot`, а не в корне публичного сайта. SQLite хранит принятые сообщения, обработанные ID и смещение Telegram; повторная доставка одного сообщения не добавляет вторую запись. Занятие продолжается после перезапуска процесса. Работать должен **один экземпляр** процесса на токен. Если для этого бота раньше был настроен webhook, сначала отключите его в Telegram Bot API, не удаляя ожидающие обновления: режим long polling несовместим с активным webhook.

## 3. Ежедневный сценарий

1. `/new` или `/new Домашнее задание к пятнице`. Если начать сразу с пересланных сообщений, занятие создастся автоматически.
2. Перешлите сообщения **в исходном порядке**: условие → соответствующее аудио. Можно выделить и переслать весь блок сообщений. Не сортируйте отдельно все тексты, а затем все записи, если их соответствие неизвестно.
3. `/status` показывает количество принятых текстов и записей. Приложение не подтверждает каждый файл отдельным сообщением, чтобы не засорять чат при сотнях записей.
4. `/title описание` изменяет только дополнение к дате занятия, не названия и условия заданий.
5. Когда все записи отправлены, `/done`. Бот обрабатывает сообщения последовательно, поэтому команда завершения будет обработана после предшествующих файлов.
6. Скачайте все `.solfege` из ответа бота. Откройте «Диктанты» на сайте, нажмите «Импортировать набор» и выберите файлы из загрузок телефона. На Android файл с неизвестным расширением сначала сохраняйте в «Загрузки», а затем выбирайте системным файловым диалогом сайта.
7. Откройте занятие. Название страницы — дата первого принятого сообщения занятия (не команды `/new`) в настроенном часовом поясе плюс описание. Описание можно дополнить и на сайте.

Дополнительные команды:

- `/last` — повторно отправить последнее готовое занятие, например, если файл потерялся.
- `/cancel` — закрыть текущий черновик без добавления в сайт. Локальные файлы черновика остаются у бота до явной очистки.
- `/purge YES` — удалить **все свои** занятия, черновики и аудиофайлы с компьютера бота. Это не удаляет уже отправленные сообщения Telegram или данные браузера. Команда необратима; сначала сохраните нужные наборы.

При ошибке скачивания бот оставляет уже принятое условие. Перешлите неудавшееся аудио ещё раз. Если сообщение об ошибке касается `/done`, повторите `/done`; если набор уже был завершён, используйте `/last`.

## Буквальное сохранение и неоднозначности

- Строка `ИП №2 (т, 2). Тональность до мажор`, номера, пробелы, переносы, знаки и весь текст сохраняются как пришли от Telegram. Заголовок задания — первая исходная строка. Музыкальные сокращения не разбираются и не исправляются.
- Номер вроде `ИП №2` остаётся частью исходного текста. Приложение не подменяет его собственной сквозной нумерацией. «Позиция в наборе» — отдельный технический индикатор. Порядок задаётся ID сообщений, полученных ботом, **не числом из названия**.
- Очередь условий связывается с аудио FIFO. При нормальном порядке «текст → аудио» получается однозначная пара. Если прислать несколько условий подряд, следующее аудио получит самое раннее ещё не связанное условие. Неоднозначный или неправильно пересланный порядок восстановить автоматически невозможно.
- Тексты без аудио и аудио без текста остаются в наборе с пометкой, а не теряются. Если есть подпись аудио, она также сохраняется буквально; без отдельного условия подпись используется как текст этого задания.
- Сохраняются ID сообщений **в чате бота**, даты и `forward_origin`, который предоставил Telegram. Для аудио также сохраняются предоставленные `file_unique_id`, исходное имя файла, название и исполнитель. Telegram часто **не передаёт ID исходного сообщения из личного чата**. В таком случае приложение не выдумывает его. Если оригинальный ID доступен, например у пересланного сообщения канала, он находится в сохранённом `forward_origin.message_id`. Доступные метаданные видны в «Исходные данные Telegram».
- Для поиска конкретного задания вводите исходный номер (`№2`, `ИП №2`) или фразу. При больших наборах список разбит на страницы по 40 строк; поиск охватывает все задания, а не только текущую страницу.

## Аудиоформаты, ограничения и плеер

- Принимаются Telegram `voice` (обычно **OGG/Opus**) и `audio` (например, **MP3/M4A**), а также отправленные документом MP3, M4A, OGG/Opus, WAV, AAC и FLAC.
- Оригинальные байты не перекодируются. Воспроизведение зависит от поддержки формата браузером. Основная целевая среда — актуальный Chrome на Android; MP3, обычный M4A/AAC, OGG/Opus и PCM WAV поддерживаются. При неподдерживаемом кодеке показывается ошибка; исходный файл не повреждается. Редкий формат лучше попросить преподавателя экспортировать в MP3.
- Консервативный лимит одной записи через облачный Telegram Bot API — **20 МБ**. Большой набор бот автоматически делит примерно по 44 МБ, ниже лимита отправки документа Telegram. Импортируйте все части; их порядок импорта неважен. При повторном импорте задания не дублируются. Пропущенные части отображаются в списке занятий.
- Нужен HTTPS (или `localhost` для разработки), в том числе для проверки SHA-256. Импорт проверяет заголовок, ссылки на записи и контрольные суммы **до** записи; каждая часть добавляется одной транзакцией. Ошибка части не отменяет ранее успешно импортированные части.
- Плеер использует локальный Blob, а не ссылку Telegram с токеном. Каждая запись запускается только нажатием; конец записи и переключение задания не запускают следующую.
- Ползунок имеет шаг 0,01 с, кнопки — ±3 с. Нажатие на волну перематывает; протягивание выделяет A–B. Границы также задаются кнопками A/B и точными числовыми полями. Минимальный участок — 0,1 с.
- Скорость 0,5–1,5× использует нативный `preservesPitch`. Если браузер не умеет сохранять высоту, изменение скорости отключается. Это не распознавание нот и не изменение исходной записи.
- A–B реализован поверх HTMLMediaElement с foreground-проверкой по кадрам и дополнительным таймером. Это точная пользовательская навигация, **не гарантия сэмпл-точного монтажа**. Точность границы зависит от кодека, браузера и энергосбережения. В фоне или при заблокированном экране Android может ограничивать таймеры; для работы с коротким A–B оставляйте страницу активной.
- Волна строится только для открытой записи, без сторонних библиотек. Для записей более 5 минут или неподдерживаемого декодирования остаются ползунок и A–B. Все сотни записей одновременно в память не декодируются.
- Полная проверка ответов, ввод нот и автоматическое переключение намеренно отсутствуют. Пользователь пишет на бумаге и проверяет с преподавателем.

## Хранение и резервные копии

На сайте — отдельная IndexedDB `solfege-dictations`, версия 1: `collections`, `tasks`, `audio`, `states`. Существующая `solfege-ear-trainers-progress` не используется и не изменяется. Сохраняются последняя открытая запись, позиция (во время воспроизведения примерно каждые 2 секунды и при паузе/переходе), скорость, A–B, отметка выполнения и поиск. После аварийного закрытия возможна потеря последних секунд позиции, но не уже зафиксированных записей.

В меню занятия «Описание занятия и резервная копия» → «Экспорт занятия» подготовьте и скачайте **каждую** часть. В копию входят исходное аудио и условия, описание, позиции и отметки. На новом устройстве импортируйте части; при импорте в уже используемую базу существующие отметки и описание не перезаписываются.

Данные привязаны к браузеру, профилю и origin. Очистка сайта, приватный режим и нехватка места могут удалить их. Кнопка «Защитить хранение» запрашивает `navigator.storage.persist()`, но браузер может отказать; резервная копия всё равно необходима. Импорт после исчерпания квоты отменяет запись текущей части, не стирая другие занятия.

На компьютере бота — закрытый каталог с SQLite и оригиналами, по пользователям и UUID занятия. Он не должен обслуживаться веб-сервером. В Telegram остаются пересланные сообщения и отправленные документы; удаление в браузере или `/purge YES` не удаляет историю у Telegram. При работе с материалами преподавателя учитывайте разрешение на хранение; не коммитьте их в публичный репозиторий.

Плеер после импорта не обращается к Telegram. Service worker не добавлялся: для открытия или перезагрузки самого сайта может понадобиться сеть. Уже открытая страница использует локальное аудио.

## 4. Постоянный запуск на Linux/VPS

На статическом Tuqo публикуются только файлы сайта через прежний Git CD. Бота запустите **отдельно**, иначе после закрытия терминала он перестанет принимать сообщения. Входящие порты, webhook, HTTPS-сертификат для бота и отдельная база данных-сервис не требуются — используется long polling и SQLite.

Пример для Debian/Ubuntu с systemd (пути в `bot/solfege-dictations.service` при необходимости исправьте):

```sh
sudo apt-get install python3 tzdata
sudo useradd --system --home /var/lib/solfege-dictations --shell /usr/sbin/nologin solfege-bot
sudo install -m 600 bot/.env.example /etc/solfege-dictations.env
sudo nano /etc/solfege-dictations.env
sudo install -m 644 bot/solfege-dictations.service /etc/systemd/system/solfege-dictations.service
sudo systemctl daemon-reload
sudo systemctl enable --now solfege-dictations
sudo systemctl status solfege-dictations
```

До запуска разместите код репозитория в `/opt/solfege-ear-trainers`, доступный сервису на чтение. В приватном env-файле заполните токен, разрешённые ID и адрес сайта; `DICTATION_DATA_DIR=/var/lib/solfege-dictations`. Если пользователь сервиса уже есть, повторять `useradd` не нужно. На сервере без systemd достаточно постоянно работающего процесса Python с тем же окружением под непривилегированным пользователем.

Наблюдение: `journalctl -u solfege-dictations` (код не выводит токен, URL скачивания или тексты условий). Следите за свободным диском. Автоматического удаления материалов нет; для очистки используйте осознанно `/purge YES`. Перед обновлением бота остановите сервис, сохраните закрытую копию каталога данных, обновите код и запустите снова. Действующие SQLite-таблицы создаются через `IF NOT EXISTS`; новые миграции должны быть добавочными, без удаления старой базы.

## Проверки и развитие

```sh
python3 -m unittest discover -s bot -p 'test_*.py' -v
python3 tests/make_dictation_fixtures.py
python3 -m http.server 8000
```

Откройте `http://localhost:8000/tests/dictation-tests.html`. Это проверки на синтетических WAV и, если установлен FFmpeg, OGG/Opus, во временных базах. Они не используют личную историю. Проверяются формат Python → браузер, буквальный текст, порядок, дубликаты, контрольные суммы, конфликт/откат, части, экспорт отметок, плеер, A–B, отсутствие автоперехода и ширины 432/393 px. Браузеру может понадобиться разрешить звук на локальном сайте.

Переносимый формат версии 1: UTF-8 magic `SOLFEGE-DICTATION\n`, 4-байтовая длина JSON (little endian), JSON-манифест, затем исходные аудиоблоки в порядке `assets`. В манифесте независимые ID занятия/задания, исходный порядок и текст, метаданные Telegram, размеры и SHA-256 записей, номера частей. Неизвестная версия отклоняется без удаления данных. Формат и IndexedDB имеют отдельные версии. Для развития можно добавить другой источник импорта или приватную синхронизацию, не меняя плеер и не включая токен Telegram в сайт.

Проверка на реальном Android и живой обмен с вашим Telegram-ботом выполняются после создания бота и настройки владельцем. Они не подменяются локальными автоматическими тестами.
