## Быстрый запуск

Запустите локальный сервер (для общей истории всех упражнений страницы должны открываться с одного адреса сайта):

```sh
python3 -m http.server 8000
```

Адрес: `http://localhost:8000/`. Никаких npm, Node.js, серверной базы данных или сборки не требуется. Каждое упражнение содержит встроенные MP3-сэмплы пианино и электропиано; синтезатор на Web Audio API остаётся резервным вариантом. История сохраняется в IndexedDB браузера. Сайт загружает только собственные статические файлы; статистика никуда не отправляется.

## Локальный прогресс

- Ссылка «Мой прогресс» на главной открывает общие показатели, регулярность, личные рекорды, последние 20 тренировок и детализацию по упражнению и режиму. Полная история доступна через экспорт.
- Текущий уровень — точность последних 30 ответов **в выбранном режиме**; до 30 ответов оценка предварительная. Число голосов, тембр, ключ, язык и тип интервала не смешиваются. График показывает скользящую точность на конец каждого активного дня (до 60 последних дней с ответами).
- Один ответ записывается при окончательной проверке. Повторы и незавершённый выбор голоса не учитываются. Тренировка начинается с первого ответа; сброс, перезагрузка и перерыв более 30 минут начинают новую. Пустые запуски не считаются тренировками. Дни учитываются по местной дате ответа; текущая серия сохраняется, если последнее занятие было вчера.
- «Сбросить» в упражнении очищает текущие счётчики, но не историю. Полное удаление истории — только на странице прогресса, с подтверждением. После удаления новые ответы записываются заново.
- JSON-импорт объединяет историю, пропускает идентичные ответы по идентификатору, проверяет весь файл и откатывается целиком при конфликте. Поддерживается до 20 МБ / 100 000 ответов за импорт. Неизвестные версии файла отклоняются без изменения данных.
- База `solfege-ear-trainers-progress`, версия 2: версия 1 создаёт записи ответов и индексы упражнения/времени, версия 2 добавляет индекс тренировки. Миграции только добавляют структуру, не удаляют ответы. Версия JSON-формата — 1, не привязана к версии кода. Не менять имя базы при выпуске обновлений. При добавлении полей/индексов повышать версию и сохранять старые данные; никогда не удалять базу в обработчике ошибки открытия.
- Запись асинхронна и не управляет игровыми таймерами. Если IndexedDB недоступна или заполнена, игра продолжает работать, а пользователь получает предупреждение о несохранении истории.
- История привязана к origin (протокол, домен, порт) и профилю браузера. `localhost`, `127.0.0.1` и публичный домен имеют разные истории. Для переноса используйте JSON. Очистка браузера, приватный режим и вытеснение данных браузером могут удалить историю; экспортируйте резервную копию. Старые тренировки до добавления истории восстановить невозможно.

Проверки без установки зависимостей: откройте `/tests/progress-tests.html`, `/tests/progress-integration.html` и `/tests/progress-page-tests.html` на локальном сервере. Они используют временные базы, не затрагивая историю пользователя. Интеграционные проверки воспроизводят звуки упражнений.

## Основные правила

### Музыкальные диктанты

Новый раздел доступен по ссылке «Диктанты» на главной. Личный бот принимает пересланные сообщения «текст → аудио», буквально сохраняет условия и выдаёт файл `.solfege`. Один импорт файла на сайте добавляет занятие с датой и необязательным описанием. Аудио и позиции остаются в браузере, исходный порядок и нумерация преподавателя не переименовываются. Есть поиск, страницы списка, отметки, перемотка, волна, ±3 с, A–B и скорость с сохранением высоты. Конец записи не переключает задание.

Сайт по-прежнему статический. Бот запускается **отдельным процессом** на компьютере/VPS с исходящим доступом к Telegram. Действующий токен создаётся владельцем через @BotFather и хранится только в приватном окружении бота, не в сайте. Аудиофайлы не размещаются в публичном репозитории. Подробные инструкции запуска, systemd, ограничения форматов, резервное копирование и тесты: **[DICTATIONS_SETUP.md](DICTATIONS_SETUP.md)**.

### Тренажёры

В №8 после ошибки разбор играет короткую мелодию-ассоциацию с названием рядом с правильным ответом, после паузы 350 мс — низкий звук, высокий, затем оба вместе. Первые два звучащих звука мелодии совпадают с нижней и верхней нотами вопроса. В нисходящем мелодическом задании ассоциация пропускается; гармоническое звучание считается ненаправленным. Тембр тот же, что в задании. Ассоциации содержат не более пяти звучащих нот: «Челюсти» и «Катюша» — по четыре, «Take On Me» — три, остальные — по пять. Для большой терции используется Louis Armstrong — «What a Wonderful World»: «I see trees of green», F → A → B♭ → D → F. Темпы взяты по нотам и записям, а не единые 140 BPM: «Челюсти» — 54, «Катюша» — 96 (замедленный учебный), «Подмосковные вечера» — 66, «What a Wonderful World» — 72, Гимн России — 76, «Звёздные войны» — 100, «Прекрасное далёко» — 91, «Ёлочка» — 120, RHCP — 88, «Take On Me» — 169. Подсказки длятся примерно 1,3–4,3 с; длиннее других звучат медленные «What a Wonderful World» и «Take On Me». Кнопка повтора доступна и во время разбора: прежняя цепочка останавливается, новая начинается заново, без повторной записи ответа. Автопереход ждёт завершения всей цепочки.

Переиспользуемый модуль `interval-associations.js` содержит все 12 фрагментов (включая тритон и октаву для будущих упражнений). `IntervalAssociations.get(distance)` возвращает `{name, notes, bpm, gate}`, где `notes` — пары `[semitones, beats]`: смещение от нижней ноты и длительность в четвертных долях; `null` вместо смещения обозначает паузу. Шаг до следующего события равен `beats × 60 / bpm`, длительность звучания — шагу, умноженному на `gate` (по умолчанию 1; для RHCP — 0,65). Паузы не создают аудиоисточников, но учитываются в `duration(distance)`, возвращающем общую длительность. `createPlayer(note)` принимает текущий аудиодвижок `note(midi, startAudioTime, seconds, volume)`, возвращающий источник с методом `stop()`. Методы проигрывателя: `play(distance, lowerMidi, startAudioTime)` и `cancel()`. Модуль не создаёт AudioContext и не загружает записи: он планирует сэмплы существующего движка и отменяет также ещё не начавшиеся звуки. Вопросы, статистика и другие упражнения не изменены.

Ритм и высоты RHCP сверены с [нотной записью на сайте David Stanley Guitar](https://davidstanleyguitar.com.au/wp-content/uploads/2023/05/Red-Hot-Chili-Peppers-Cant-Stop-5-2.pdf-2.pdf): страница 1, начало Riff A, такт 7, четверть = 88. Теперь используются только первые пять звучащих нот и пауза между первой и второй: две четвертные доли (1,36 с), а не весь такт. Это фортепианная адаптация: без шума гитарных ударов, с равномерным коротким снятием нот, а не имитация оригинального гитарного тембра.

Малая секста: первые пять нот припева «Прекрасного далёко», 2,5 четвертных доли (1,65 с при 91 BPM), без продолжения фразы. Квинта: первые пять нот «Звёздных войн», 2,7 с при 100 BPM вместо 5,79 с; соотношение длительностей сохранено. В подключении словаря указан параметр версии, чтобы браузер не сохранял прежние длинные фразы после обновления страницы.

«Катюша» (большая секунда): только слово «Расцветали», четыре ноты, два такта 2/4 (2,5 с). Ритм сверен с [нотами для двух домр и фортепиано](https://domranote.ru/ansambli/note/Блантер%20М.%20Катюша%20(д+д).pdf), страница 1, начало мелодии у цифры 2: длительности в четвертях `1.5, 0.5 | 1.5, 0.5`. Темп снижен со 112 до 96 BPM по замечанию о слишком быстром звучании; оба пунктирных оборота сохранены.

Большая терция: «What a Wonderful World» записана по [лёд-листу](https://www.jazztutorial.org/wp-content/uploads/2020/03/what-a-wonderful-world-lead-sheet.pdf) и [официальной публикации](https://www.musicnotes.com/sheetmusic/louis-armstrong/what-a-wonderful-world/MN0053148) (F major, 72 BPM). Фраза «I see trees of green»: F → A → B♭ → D → F, то есть `0 → 4 → 5 → 9 → 12` полутонов; первые две ноты — большая терция. Ритм в четвертях: `0.5, 0.5, 1.5, 0.5, 2`. Прежняя «Весна» Вивальди удалена.

Гимн России воспроизводится при 76 BPM — официальном темпе музыкальной редакции; прежние 140 BPM были заметно быстрее. Для «Подмосковных вечеров» взято 66 BPM, для «Прекрасного далёко» — 91 BPM, для «Звёздных войн» — 100 BPM, для «Челюстей» — 54 BPM, для «Ёлочки» — 120 BPM.

Большая септима: «Take On Me» исправлено по [вокальной партии, страница 4](https://sheetsfree.com/sheets/A/A-ha%20-%20Take%20On%20Me.pdf). Оставлены только слова «Take — on — me»: ля малой октавы → соль-диез первой → ля первой, то есть `0 → 11 → 12` полутонов от нижней ноты вопроса. Все три ноты — целые (по четыре четверти); при 169 BPM фраза длится 4,26 с. Первые две ноты точно образуют восходящую большую септиму; третья поднимается на полтона, а не опускается, как в прежней ошибочной записи. Повтор неправильной тройки удалён. Это исправление заменяет прежние утверждения об «исправленной» фразе a-ha.

В упражнении 8 «Все интервалы» выберите малую или большую секунду, терцию, сексту или септиму либо чистую кварту или квинту. Переключатели «Электро / Пианино» и «Мелодич. / Гармонич.» задают звучание; по умолчанию — пианино и две ноты одновременно. На телефонах они укладываются в одну строку: «Мелодич./Гармонич.» слева, «Электро/Пианино» справа; шрифт 12 px, высота кнопок 38 px. Карточка не растягивается на всю высоту экрана: статистика идёт сразу под ней, пустые блоки отзыва не резервируют место, декоративная серая полоса удалена. Оба звука остаются в C3–B5 (малая, первая и вторая октавы). Ошибочные интервалы появляются чаще, верные ответы постепенно снижают их вес; веса сохраняются, одинаковых интервалов подряд нет. При разборе в №5, №6 и №8 звучат первая нота, вторая, затем обе вместе; верный ответ сопровождается конфетти. С клавиатуры кнопкам по порядку соответствуют `1`–`9` и `0`. Режимы сохраняются в «Моём прогрессе» под ID `intervals-all`; история упражнений 5 и 6 не меняется.

Карточка упражнения 7 открывает `note-shooter.html`. Играйте ближайшую ноту справа от линии ответа (38% ширины), не дожидаясь пересечения. При 80 ударах/мин путь занимает 8 бит = 6 секунд; ноты появляются каждые 2 бита = 1,5 секунды. Верное попадание убирает ноту, добавляет очко и выпускает зелёное название ноты без октавы — оно летит вверх. При ошибке или пропуске от ноты летит вниз красное название без октавы; ошибочная нота за 0,6 секунды врезается в корабль и отнимает жизнь, а следующая цель активна сразу. Разгон не влияет на другие ноты. После трёх столкновений — итоги и «Ещё раз» (в расширенном диапазоне жизней пять).

Настройки аркады доступны до игры и после неё: скрипичный/басовый ключ, базовый/расширенный диапазон, 40–160 ударов/мин с шагом 10. Границы находятся в `NoteShooter.CONFIG.ranges`: скрипичный C4–B4 / B3–B5; басовый G2–A3 / E2–C4. Не больше одной добавочной линейки с каждой стороны. В базовом диапазоне три жизни, в расширенном пять. Только натуральные ноты, без одинаковых подряд. Рекорд — максимальная серия в этом браузере для выбранных ключа, диапазона и темпа; он хранится отдельно от настроек и не смешивается между режимами. Пауза останавливает ноты и приём ответов, выключает микрофон; возвращение требует «Продолжить» и нового нажатия клавиши. Игра ничего не воспроизводит; короткая пауза после ответа и ожидание спада/новой атаки через `pitch-detector.js` не дают удерживаемой ноте засчитаться повторно.

Режим «Оба ключа» показывает фортепианную систему: скрипичный стан сверху, басовый снизу. Ноты выбираются из объединения двух диапазонов прежним взвешенным алгоритмом; общие ноты не получают двойной вес. Ниже C4 они показаны на басовом стане, от C4 — на скрипичном. По-прежнему играется одна нота за раз: цель — ближайшая к линии нота из общей очереди обоих станов. Корабль и подписи следуют высоте нужного стана. Адаптивные ошибки сохраняются по MIDI, жизни, серии и победы не меняются; в прогрессе «Оба ключа» — отдельный режим.

Чтобы короткая верхняя нота не смешивалась с предыдущей, аркада анализирует последние 44 мс с более частой дискретизацией. Индикатор выводит название после подтверждения, иначе может показать «Уточняю ноту…». Попадание засчитывается по двум совпадающим кадрам, неверная нота — по трём: так короткая верхняя нота не теряется из-за одного смазанного кадра, а случайный звук не отнимает жизнь. Для верхних нот попадание дополнительно проверяется по расстоянию до нужной частоты: до 70 центов, даже если округление уже перешло к соседнему полутону. Это покрывает растянутый строй цифрового пианино, когда нота стоит у границы. Для прототипа сохранён исходный профиль детектора.

Аркада запоминает ошибки по каждой ноте в localStorage отдельно для каждого ключа и диапазона. Нота, у которой ошибок больше среднего по диапазону, выпадает чаще — до пяти раз, но одна и та же нота никогда не идёт дважды подряд. После верных ответов вес плавно снижается, пока частота не выровняется. Корабль плавно перемещается по вертикали на высоту ближайшей ноты: при движении выхлоп становится длиннее, а корпус слегка наклоняется в сторону движения. После 50 верных подряд над нотным станом взлетают звёзды и пролетает корабль, все жизни восстанавливаются, а темп растёт на 10 (до 160 ударов/мин). Повышение действует только до конца текущей игры: выбранный в настройках темп не перезаписывается, следующая игра начинается с него, а текущий темп волны виден в шапке рядом с паузой. Затем счёт следующих 50 начинается заново.

В прогрессе аркада имеет отдельный ID `note-shooter`; режим включает ключ, диапазон и темп. На ноту записывается один окончательный вердикт (`task`: `MIDI:correct`, `MIDI:wrong` или `MIDI:timeout`), при столкновении второй записи нет. Асинхронная запись не управляет игровым временем. Старые ответы прототипа `play-the-note` сохранены. Имя и версия IndexedDB не менялись.

#### Верхний регистр в аркаде

Дополнительный диапазон «Верхний регистр» ограничивает скрипичные ноты D5–B5 (ре–си второй октавы), басовые F3–C4 (фа малой — до первой): нижняя граница на второй линейке сверху. В режиме «Оба ключа» до первой остаётся на басовом стане. Пять жизней; рекорд и адаптивные веса сохраняются отдельно от базового/расширенного диапазонов.

#### MIDI-ввод в аркаде

В настройках есть «Микрофон / MIDI / Авто» (по умолчанию «Авто»). По «Старт» запрашивается `requestMIDIAccess({sysex:false})`; при отсутствии API, отказе или отсутствии входных портов используется прежний микрофонный путь. «Микрофон» не принимает MIDI-ответы даже при подключённом инструменте. «MIDI» и «Авто» принимают все подключённые входные порты; выходные порты не используются, MIDI-режим не создаёт AudioContext.

Note-on с ненулевой velocity отвечает один раз. Note-off и note-on с velocity 0 освобождают клавишу; удержание не повторяет ответ. Первые note-on собираются в окно 40 мс, чтобы аккорд давал одну ошибку, а не попадание по первой ноте. Перед следующей попыткой отпустите все клавиши. Пауза, заставка победы, скрытие страницы и конец игры отменяют ожидающий ответ. В режиме «Авто» подключение MIDI переключает ввод с микрофона; отключение последнего MIDI-порта ставит игру на паузу — «Продолжить» подключает микрофон или вернувшийся инструмент.

Для обычного браузера на Android нужен Chrome (Firefox на Android не поддерживает Web MIDI). Safari на iPad не поддерживает Web MIDI: там работает микрофон. Возможная альтернатива — [MIDIWeb Browser от 5of12](https://apps.apple.com/app/midiweb-browser/id6757226617), предоставляющий нативный MIDI-доступ сайтам; с реальным iPad/USB-пианино он пока не проверен. Совместимость проверяется по наличию API, без определения браузера по имени.

Прежний прототип по-прежнему доступен напрямую по `play-the-note.html`:

«Сыграй ноту»: нажмите «Старт», разрешите микрофон и играйте по одной ноте без педали. После ответа отпускайте клавишу и дожидайтесь затихания. Доступ к микрофону работает по HTTPS и на localhost, но **не по обычному HTTP с LAN-IP**. Для iPad используйте опубликованный HTTPS-сайт. Аудио остаётся в браузере, не записывается и никуда не отправляется. При скрытии страницы микрофон выключается; для продолжения нажмите «Старт».

Настройки ключа, диапазона, знаков, A4, допуска, сигнала и видимости таймера сохраняются локально. В прогресс попадает только первый уверенный ответ на карточку: последующие попытки не меняют точность и серию. Режим кодирует ключ, диапазон и знаки в поле `direction` без изменения схемы хранилища. Стабильность означает три кадра одного MIDI в пределах ±20 центов от первого кадра; допуск проверяется отдельно относительно целевой частоты. Реальные показатели задержки и точности требуют ручного испытания на iPad.

Низкие ноты показываются в басовом ключе, высокие — в скрипичном, без упражнений на чрезмерные добавочные линейки. Фактические задания — пересечение выбранного диапазона с C4–C6 для скрипичного или C2–B3 для басового ключа. В режиме «Оба» отображается фортепианная система: ключ выбирается случайно, нота берётся из его части диапазона.

- Интерфейс на русском языке.
- Не менять игровой процесс, звук, таймеры, статистику, конфетти и адаптивную вёрстку без отдельного запроса.
- Браузер разрешает звук после действия пользователя: нажмите стартовую кнопку.
- Электронный и акустический режимы переключаются внутри каждого упражнения.
- Второе упражнение **не сообщает заранее число голосов**; «Средний» для двухголосного случая неверен. Второй сигнал — **одна изменённая нота**, а не новое созвучие.
- Повтор разбора ошибки не влияет на статистику и не должен отменять переход к следующему вопросу.

## Публикация

См. [DEPLOY.md](DEPLOY.md). Рекомендуемая схема: GitHub как репозиторий, Tuqo с российской инфраструктурой как публичный сайт. Адрес публикации выдаст хостинг после подключения аккаунта.

### Адреса сайта

- Исходники: https://github.com/shprekher/solfege-ear-trainers
- Главная: https://solfeggio.tuqo.ru/
- «Выше или ниже?»: https://solfeggio.tuqo.ru/half-step.html
- «Сколько нот?»: https://solfeggio.tuqo.ru/count-notes.html

- Диктанты: https://solfeggio.tuqo.ru/dictations.html

Tuqo Git CD подключён к публичному HTTPS-адресу репозитория и ветке `main`; вебхук GitHub передаёт события `push`. Сборка и npm не нужны. Секрет вебхука хранится в настройках сервисов, не в репозитории.

По отдельному запросу владельца в первом упражнении добавлены показатели «Ответов» и «Рекорд», оформление строки статистики взято из второго упражнения. Алгоритм подсчёта результатов не менялся. Проверки и ограничения описаны в [TESTING.md](TESTING.md).
