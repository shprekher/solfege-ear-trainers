# Инструкции для OpenCode

## Задача

Это готовый статический сайт с тремя тренажёрами сольфеджио. По запросу пользователя: проверить, загрузить на GitHub и развернуть на хостинге, доступном в РФ без VPN. Основной путь: GitHub -> Tuqo Git CD. Никакой сборки нет, `index.html` должен находиться в корне репозитория и опубликованного сайта.

## Что нельзя ломать

- **Не переписывать** `count-notes.html` и `shifted-voice.html` при первой публикации: это итоговые, проверенные пользователем самостоятельные HTML-страницы.
- Не удалять встроенные piano MP3 из JavaScript: они обеспечивают автономную работу без внешних CDN.
- Не менять громкость, электронный/пианино режимы, алгоритм генерации вопросов, паузы, анимацию, статистику и обработку ошибочного ответа.
- Второе упражнение: сначала одновременно играют 2 или 3 ноты; спустя паузу играет **одна** нота, смещённая на полтона вверх/вниз относительно одного из голосов. Всегда три кнопки «Нижний», «Средний», «Верхний»; для 2 голосов «Средний» заведомо неверен. Затем ответ вверх/вниз.
- На этапе разбора одна кнопка показывает «Повторить объяснение», на этапе задания — «Повторить вопрос»; многократный повтор разбора не должен ломать автопереход.
- Не добавлять внешние шрифты, трекеры и загрузку аудио из внешней сети.
- Все публичные тексты — на русском.

## Проверки до публикации

1. Статически проверить ссылки из `index.html` и что файлы существуют.
2. Запустить `python3 -m http.server 8000` и проверить: `/`, `/half-step.html`, `/count-notes.html`, `/shifted-voice.html` возвращают HTTP 200.
3. Открыть в браузере; проверить JavaScript console, нажатие «Начать» и звук (звук может не воспроизводиться без пользовательского клика).
4. Проверить оба режима звука, корректный и ошибочный ответ, повтор и автопереход, статистику.
5. Проверить без горизонтальной прокрутки на условных размерах 432×934 (Honor Magic 7 Pro) и 393×852 (iPhone 15), по возможности именно в Safari iOS.
6. При тестировании подтверждать фактически выполненное; не заявлять о тесте Safari или доступности из России, если не было реальной проверки.

## Публикация и безопасность

- Публиковать только по поручению пользователя и через его учётные данные/авторизацию. Если GitHub или хостинг не авторизован — попросить пользователя пройти вход, не запрашивать пароль в чате.
- Желательно публичный репозиторий `solfege-ear-trainers` и ветка `main`, если пользователь не указал другого; не перезаписывать существующий репозиторий без проверки.
- Не коммитить токены, пароли, ключи, cookie и `.env`.
- После `git push` подключить GitHub-репозиторий на Tuqo (Git CD -> GitHub -> repo -> main). Не придумывать URL: взять фактический адрес из панели.
- Tuqo может не работать из отдельной сети РФ; после публикации предложить проверку URL в российской сети.
- `THIRD_PARTY_LICENSES.md` — важная часть поставки; не удалять attribution/GPL из файлов.
- Перед коммитом/публикацией проверить `git diff` и попросить согласовать любые существенные изменения логики.

## Архитектура

Чистые HTML/CSS/JS-файлы без зависимостей. `index.html` — только каталог; игровые страницы автономны. GitHub Pages — необязательный резервный вариант; для показа преподавателю в России приоритет российский хостинг.
